# 01-工程实施说明书

## 1. 实施原则
- **先验证能力，再开始制作。**
- 不假设用户的 Codex 当前版本已经支持某种具体宠物格式；需要先在运行环境中核查。
- 不修改 Codex 安装文件，不使用高风险注入方案作为默认路线。
- 优先使用官方支持的工作流（如果存在），例如宠物、技能、资源导入、动画图集等。

## 2. 第一轮任务（建议交给 Codex 的范围）
1. 检查用户当前 Codex 版本。
2. 检查是否存在 Pets / hatch-pet / sprite sheet / 自定义宠物资源机制。
3. 明确支持的资产格式：
   - 独立 PNG？
   - 透明背景素材？
   - sprite sheet？
   - 帧数与尺寸限制？
4. 评估双形态能否在同一个宠物中依据状态切换。
5. 列出“可以做 / 做不到 / 需要验证”的事项。

## 3. 若官方宠物工作流存在，应重点验证
- 状态枚举（idle / move / wave / think / work / error / complete 等）
- 单宠物是否可多服装/多状态切换
- 对话气泡/台词是否可显示
- 资源命名、尺寸与导入方式
- 本地预览流程与调试方法

## 4. 建议的后续实现阶段
### 阶段 A：能力核实
输出：一份兼容性与方案评估结果。

### 阶段 B：美术资产扩展
基于本交付包中的两张已确认母版，继续制作：
- 日常形态：待机、开心、发呆、生气/催促、提示
- 工作形态：专注、思考、执行、报错、完成

### 阶段 C：资产整理
根据 Codex 实际要求，整理为：
- 独立 PNG（透明背景）
- 或 sprite sheet / atlas
- 或其他官方要求的包结构

### 阶段 D：接入与调试
- 导入宠物
- 检查显示尺寸
- 检查深色界面适配
- 检查状态切换逻辑
- 记录不可实现的部分

## 5. 验收重点
- 人物比例不跑偏
- 校服与战斗服是同一角色体系
- 工作形态的下半身比例自然，不出现臀胯鼓包、腿部拥挤问题
- 缩小到宠物尺寸后仍有良好辨识度
- 若实际接入有限制，优先保证核心形象质量
